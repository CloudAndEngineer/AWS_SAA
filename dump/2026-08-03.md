어떤 솔루션이 이러한 요구 사항을 충족할까요?

  * A: AWS CLI를 사용하면 업로드는 가능하지만, 최소한의 네트워크 대역폭 사용이라는 조건을 만족하지 못함. 또한 대용량 데이터를 전송하는 데는 적합하지 않음

  * C: File Gateway는 지속적인 하이브리드 파일 공유에 적합한 수단이지, 일회성 대규모 마이그레이션에 적합한 수단이 아니다. 결국에는 모든 파일을 네트워크로 전송해야 한다.

  * D: 전용 회선 서비스인 Direct Connect를 이용하면 인터넷 업로드보다 속도는 빠르지만, 약 1Gbps의 높은 대역폭을 사용해야 한다. 이 대역폭으로 70TB 데이터를 전송하려면 약 8일 정도 소요되므로 경우에 따라 Snowball Edge가 더 빠를 수도 있다.


7. 어떤 회사에 수신 메시지를 수집하는 애플리케이션이 있습니다. 수십 개의 다른 애플리케이션과 마이크로서비스가 이 메시지를 빠르게 소비합니다. 메
시지 수는 크게 다르고 때로는 초당 100,000개로 갑자기 증가합니다. 이 회사는 솔루션을 분리하고 확장성을 높이려고 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

  * A: Amazon Kinesis Data Analytics는 실시간 SQL 분석 서비스이므로 문제의 요구사항과는 맞지 않는다.

  * B: Auto Scaling은 수집 애플리케이션 자체를 확장시킬 수는 있지만, 여러 소비자에게 전달하는 메시지 브로커의 역할은 하지 못한다. 또한 같은 인스턴스에 애플리케이션들이 강하게 결합되어 있다는 점을 해결할 수 없다.

  * C: 요구사항에 비해 해결 방법이 지나치게 복잡하다. Amazon Kinesis Data Streams는 대규모 실시간 데이터 스트리밍 서비스인데, 여러 개의 샤드에 데이터를 분산 저장하는 방식을 사용한다. 단일 샤드는 최대 Input: 1MB/s, Output: 2MB/s, 1000 Record/s의 속도를 제공하는데, 문제의 초당 레코드 처리 수를 절대 만족할 수 없다.

  * D: 발행된 메시지를 SNS에 게시하고 여러 소비자가 SQS로 구독하는 구조는 문제를 해결하기에 적합하다. SNS가 메시지를 Publish하면 이 메시지가 모든 SQS에 복시된다. 따라서 모든 애플리케이션이 메시지를 독립적으로 처리할 수 있다.
