10. 한 회사가 AWS에서 전자상거래 웹 애플리케이션을 구축하고 있습니다. 이 애플리케이션은 새로운 주문에 대한 정보를 Amazon API Gateway REST API
로 보내 처리합니다. 이 회사는 주문이 수신된 순서대로 처리되도록 하려고 합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

  * A: SNS + Lambda를 사용하면 주문이 들어온 순서대로 처리된다는 것을 보장할 수 없다. SNS를 사용하면서 요구 조건을 만족하려면 반드시 (SNS FIFO + SQS FIFO) 조합을 활용해야 한다.

  * B: 메시지 순서가 보장되고 모든 메시지는 각각 한 번씩만 전송되므로, 요구 사항을 만족한다.

  * C: API Gateway Authorizer는 인증과 권한 부여를 담당하므로 메시지 순서와는 상관이 없다. 주문이 들어오는 동안 서비스를 차단하는 것은 비효율적이다.

  * D: SQS Standard Queue는 순서를 맞추기 위해 노력을 하지만 완전히 보장하지는 않으므로, 간혹 중복 주문이 발생하거나 순서가 뒤바뀔 수도 있다.


11. 한 회사에는 Amazon EC2 인스턴스에서 실행되고 Amazon Aurora 데이터베이스를 사용하는 애플리케이션이 있습니다. EC2 인스턴스는 로컬 파일에
저장된 사용자 이름과 비밀번호를 사용하여 데이터베이스에 연결합니다. 이 회사는 자격 증명 관리의 운영 오버헤드를 최소화하려고 합니다.
솔루션 아키텍트는 이 목표를 달성하기 위해 무엇을 해야 할까요?

  * A: Secrets Manager는 자동 회전 기능을 제공하므로 요구 사항을 만족한다.

  * B: Systems Manager Parameter Store는 암호 저장 기능을 제공하지만, 자동 회전 기능을 기본적으로 제공하지는 않는다. (구현 가능하지만 비용 증가)

  * C, D: 운영 개선 효과가 전혀 없다.


12. 글로벌 기업이 애플리케이션 로드 밸런서(ALB) 뒤의 Amazon EC2 인스턴스에서 웹 애플리케이션을 호스팅합니다. 웹 애플리케이션에는 정적 데이터와
동적 데이터가 있습니다. 이 회사는 정적 데이터를 Amazon S3 버킷에 저장합니다. 이 회사는 정적 데이터와 동적 데이터의 성능을 개선하고 지연 시간
을 줄이려고 합니다. 이 회사는 Amazon Route 53에 등록된 자체 도메인 이름을 사용하고 있습니다.
솔루션 아키텍트는 이러한 요구 사항을 충족하기 위해 무엇을 해야 합니까?

  * A: CloudFront는 정적 콘텐츠를 캐싱하고 동적 콘텐츠를 AWS 글로벌 백본 망을 통해 더 빠르게 전달한다. 하나의 도메인을 사용하며 Route53와도 연동된다.

  * B: AWS Global Accelerator는 S3 Bucket을 엔드포인트로 설정할 수 없다.

  * C: CloudFront 앞에 Global Accelerator를 두는 것은 일반적인 설계가 아니다. 정적 콘텐츠는 이미 CloudFront가 처리하고 있다.

  * D: Global Accelerator는 S3를 엔드포인트로 사용할 수 없고 사용자가 두 개의 도메인을 사용해야 한다.


13. 한 회사가 AWS 인프라에 대해 월별 유지 관리를 수행합니다. 이러한 유지 관리 활동 중에 회사는 여러 AWS 지역에서 Amazon RDS for MySQL 데이터
베이스의 자격 증명을 순환해야 합니다.
어떤 솔루션이 가장 적은 운영 오버헤드로 이러한 요구 사항을 충족할까요?

  * A: 모든 요구사항을 만족한다.

  * B: Systems Manager Parameter Store는 자동 회전 기능을 제공하지 않고, 다중 리전 복제 기능도 지원하지 않는다.

  * C, D: 요구 사항을 모두 만족하는 관리형 서비스가 있는데, 굳이 수동으로 구현하고 있으므로 비효율적이다. 운영 오버헤드가 너무 크다.


14. 한 회사가 애플리케이션 로드 밸런서 뒤의 Amazon EC2 인스턴스에서 전자상거래 애플리케이션을 실행합니다. 인스턴스는 여러 가용성 영역에 걸쳐
Amazon EC2 자동 확장 그룹에서 실행됩니다. 자동 확장 그룹은 CPU 사용률 메트릭에 따라 확장됩니다. 전자상거래 애플리케이션은 대규모 EC2 인스
턴스에 호스팅된 MySQL 8.0 데이터베이스에 트랜잭션 데이터를 저장합니다.
애플리케이션 부하가 증가함에 따라 데이터베이스 성능이 빠르게 저하됩니다. 애플리케이션은 쓰기 트랜잭션보다 더 많은 읽기 요청을 처리합니다. 이
회사는 높은 가용성을 유지하면서 예측할 수 없는 읽기 워크로드의 수요를 충족하도록 데이터베이스를 자동으로 확장하는 솔루션을 원합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

  * A: Redshift는 대규모 데이터 분석 서비스이지, 트랜잭션 위주의 서비스가 아니다.

  * B: RDS Read Replica는 자동으로 인스턴스 개수를 늘리는 기능이 없다. 또한 Single-AZ이므로 가용성도 부족하다.

  * C: Aurora는 요청을 Replica에 분산한다. 읽기 요청이 증가하면 Auto Scaling을 이용하여 인스턴스 개수를 늘릴 수 있다.

  * D: 캐싱을 이용하면 DB 부하를 줄일 수는 있지만, 자동 확장은 불가능하다.


15. 한 회사가 최근 AWS로 마이그레이션했고 프로덕션 VPC에서 유입되고 유출되는 트래픽을 보호하는 솔루션을 구현하려고 합니다. 이 회사는 온프레미
스 데이터 센터에 검사 서버를 두었습니다. 검사 서버는 트래픽 흐름 검사 및 트래픽 필터링과 같은 특정 작업을 수행했습니다. 이 회사는 AWS 클라우드
에서 동일한 기능을 원합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

  * A: Amazon GuardDuty는 위협 탐지 서비스이다. 탐지는 하지만 트래픽 검사 및 필터링은 하지 않는다.

  * B: VPC Traffic Mirroring은 트래픽을 미러링하는 서비스로, 원본 트래픽이 그대로 전달되고 필터링은 하지 못한다.

  * C: AWS Network Firewall은 온프레미스 방화벽을 대체하는 서비스이므로 요구 사항을 만족한다.

  * D: Firewall Manager는 보안 정책을 중앙에서 배포하고 관리하는 서비스이지, 방화벽 그 자체가 아니다. AWS Network Firewall의 정책을 관리한다.


16. 한 회사가 AWS에서 데이터 레이크를 호스팅합니다. 데이터 레이크는 Amazon S3와 PostgreSQL용 Amazon RDS의 데이터로 구성됩니다. 이 회사는 데
이터 시각화를 제공하고 데이터 레이크 내의 모든 데이터 소스를 포함하는 보고 솔루션이 필요합니다. 회사의 경영진만 모든 시각화에 대한 전체 액세스
권한을 가져야 합니다. 나머지 회사는 제한된 액세스 권한만 가져야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

  * A: QuickSight 자체는 맞지만, 권한 관리 방식이 잘못되었다. QuickSight에서는 IAM 역할을 이용해 대시보드 접근 권한을 관리하지 않는다.

  * B: QuickSight에서는 사용자 및 그룹 별로 권한을 관리한다. QuickSight는 S3 데이터 연결, RDS 연결, 여러 데이터 소스 결합, 대시보드 생성, 권한 관리, Row-Level Security 등을 지원한다.

  * C: AWS Glue는 ETL(Extract, Transform, Load) 서비스이지, 데이터 시각화 서비스가 아니다. 또한 사용자별 권한을 분리할 수 없다.

  * D: Athena는 SQL 질의를 진행하는 서비스이다. S3 -> Athena -> Query 는 가능하지만, Athena로 데이터 시각화를 할 수는 없다. S3 버킷 정책만으로는 QuickSight처럼 경영진/직원별 권한을 쉽게 관리할 수 없다.
