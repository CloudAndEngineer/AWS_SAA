# 1. KMS

  *	AWS와 애플리케이션에서 사용하는 Key를 관리하는 서비스

  * Key를 암호화하면, 이 키를 암호화한 Key도 보호해야 함

  * 결국 최상층에 위치한 Root Key를 보호해야 함


  * Customer Managed Key

    * 사용자가 직접 만들고 관리하는 Key

	* Key를 사용, 변경, 삭제하는 주체를 정할 수 있다.

	* key에서 일어난 모든 활동은 CloudTrail에 기록된다.

	* Key Rotation 기간을 지유롭게 지정할 수 있다.

	* 엄격한 보안 규정이나 요구 조건을 만족하는 데 유용하다.


  * AWS Managed Key

    * AWS 서비스가 데이터를 암호화하기 위해 계정 내에서 자동으로 생성하고 관리하는 KMS 암호화 키

	* 사용자가 직접 수정/삭제할 수는 없다.

	* 자동 Key Rotation이 적용된다.

	* Customer Managed Key와 달리 비용이 발생하지 않는다.


# 2. Encryption

  * Envelope Encryption

    * 대용량 데이터를 안전하고 빠르게 보호하기 위해 데이터 키(DEK)로 실제 데이터를 암호화하고, 그 데이터 키를 마스터 키(CMK/KEK)로 다시 암호화하는 2단계 암호화 방식

	* 작동 방식

	* 암호화: 펑문/암호화된 데이터 키 동시 발급 -> 평문 데이터 키로 데이터 암호화 -> 평문 데이터 키를 메모리에서 삭제 -> 암호화 데이터/데이터 키 저장

	* 복호화: KMS에 암호화된 데이터 키 제공 -> KMS가 데이터 키 복호화 -> 복원된 평문 데이터 키로 암호화된 데이터를 복구 -> 평문 데이터 키를 메모리에서 삭제

	* 장점

	* 직접 마스터 키로 암호화하지 않고 가벼운 데이터 키를 사용해서 속도가 빠름

	* KMS 마스터 키 직접 암호화 시에는 용량 문제가 발생하는데, 이 문제가 해결됨


  * S3 Encryption

    * 서버 측 암호화(SSE)와 클라이언트 측 암호화(CSE)로 나뉨

	* SSE-S3(기본 옵션): AWS 관리형 키. AWS Managed Key 사용.

	* SSE-KMS: Customer Managed Key 사용. KMS를 통해 키 괸리.

	* SSE-C: 사용자가 직접 암호화 키 제공. 키는 저장하지 않음.

	* Client-Side Encryption: 사용자가 로컬에서 직접 암호화


  * EBS Encryption

    * AWS KMS Key를 이용하여 EBS 블록을 암호화

	* 암호화된 EBS 블록을 생성하고 호환되는 인스턴스에 연결하면, 다음과 같은 데이터가 암호화된다.

	* 볼륨에 저장된 데이터, 볼륨과 인스턴스 간에 이동하는 데이터, 볼륨(스냅샷)으로 생성한 스냅샷(볼륨)
